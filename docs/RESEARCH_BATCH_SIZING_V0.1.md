# 調査人数の適応運用 v0.1

作成日：2026-09-20

状態：Yuichiが人数を固定せず、実績を測りながら調整する方針を承認

## 結論

2人を固定値にしない。当面の標準は4人とし、人物同定が難しい場合は1〜2人、定型抽出が安定した場合は6人へ増やす。10人一括は、抽出とQAの再作業が十分に少なくなってから試す。

## 人数の目安

| 難易度 | 1 Waveの人数 | 例 |
| --- | ---: | --- |
| 高 | 1〜2人 | 同姓同名、双子、表記揺れ、海外資料、所属矛盾 |
| 標準 | 4人 | B.LEAGUE・クラブ・大学連盟の公式資料がある人物 |
| 低 | 6人 | 同じ公式サイト・同じ列構造から定型抽出できる人物 |
| 自動化後 | 最大10人 | URL取得と項目抽出が自動化され、直近2 Waveで再作業が少ない場合 |

## 測定項目

- 対象人数
- 公式Source数と1人あたりSource数
- Evidence数と1人あたりEvidence数
- HOLD数
- Python構造QAエラー数
- Codexによる再作業件数
- 調査開始からCANDIDATE・QA完了までの作業時間

検索件数や回答文字数は速度の指標にしない。

## 増減ルール

次の条件を満たす場合は、次のWaveを同じ人数または2人増で試す。

- 1人あたり公式Sourceが2件以上
- Python構造QAがエラー0件
- 人物取り違えやURL再調査がWave全体で1件以下
- 全対象がEvidenceまたはIssueへ結び付いている

人物同定の矛盾、直接URL不足、再調査が2件以上発生した場合は、次のWaveを2人以下へ戻す。人数は品質を落として増やさない。

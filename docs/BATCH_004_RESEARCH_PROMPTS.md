# Batch 004 — Felo・Gemini調査指示文

対象は[BATCH_004_PROPOSAL](BATCH_004_PROPOSAL.md)の10人。調査AIの回答文自体はSourceにせず、返されたURLと資料内位置をCodexが再確認してからCANDIDATE化する。

## 実行方法

10人一括では実行しない。2人ずつの5 Waveに分け、1 WaveごとにFelo、Gemini、Codex監査を完了してから次へ進む。

| Wave | 対象 | 優先理由 |
| --- | --- | --- |
| 1 | 河村勇輝、児玉ジュニア | NBA・日本代表と現役B.LEAGUE契約を最優先 |
| 2 | 河合瑠那、長岡大杜 | 特別指定、B3登録、公式戦出場の区別を確認 |
| 3 | 重冨周希、重冨友希 | 双子の人物取り違えを個別に解消 |
| 4 | キエキエ トピー アリ、遥天翼 | 現役・過去のプロCareerを更新 |
| 5 | 今泉太陽、崎濱秀真 | ドラフト候補者掲載と指名結果を分けて確認 |

各Waveの流れは次のとおり。

1. Feloは公式資料の直接URL候補だけを発見する。
2. GeminiはFeloが見つけたURLの本文を読み、資料内位置と確認値を整理する。
3. CodexがURLを開き、値、発行元、日付、人物同定を再確認する。
4. 確認できた項目だけをCANDIDATE準備へ進め、残りはHOLDにする。

人物ごとに公式資料を3件程度確保できた時点でFelo検索を止め、Gemini精査へ移る。検索件数を増やすことより、契約、登録、出場をそれぞれ裏付ける資料を優先する。

## 高速化の測定

回答文字数や検索件数ではなく、次の値で確認する。

- 1人あたりに採用できた公式Source数
- Sourceから作成できた項目別Evidence数
- 人物・組織・期間の取り違えによる再調査件数
- HOLDの理由が明確になった項目数

2人単位で誤りを早く止め、採用できるEvidenceを継続的に増やすことを高速化とする。

## Wave 1 Gemini用：発見済みURLの精査

```text
河村勇輝と児玉ジュニアについて、下に貼るFeloのURLだけを最初に開いて精査してください。不足する場合に限り、同じ発行元の公式サイト内を追加検索してください。

人物ごとに確認する項目：
1. 公式氏名、読み、英語表記、生年月日
2. 福岡第一高校との関係を直接示す記載
3. 高校後の大学・組織
4. プロ契約の種別と発表日
5. リーグ登録
6. 公式戦出場
7. 現在または最後に確認できる所属と、その情報の基準日

出力列：
人物｜対象項目｜確認値｜発行元｜ページ名｜公開日・大会日｜直接URL｜資料内位置｜具体的記載｜判定

判定：
- READY_FOR_VERIFIED_REVIEW：公式資料の該当箇所で直接確認できる
- HOLD_CANDIDATE：URL、資料内位置、期間、人物同定のいずれかが不足
- REJECT_CANDIDATE：別人、誤記、無関係資料

必須ルール：
- 契約発表だけでリーグ登録・公式戦出場済みと判定しない。
- 「現在所属」にはページの公開日または更新日を付ける。
- 学年から在籍開始・終了年月を逆算しない。
- 直接URLと資料内位置がない値をREADYにしない。

ここにFelo結果を貼る：

```

## Codex受入時の確認

- URLが実在し、対象人物の記載があるか
- 発行元、公開日、資料名が回答と一致するか
- 引用要約が実際の記載を超えていないか
- 契約、登録、出場、在籍を混同していないか
- 既存Person IDとの重複がないか
- 同じSourceでも項目別の資料内位置が記録されているか

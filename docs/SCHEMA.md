# SCHEMA — データ設計v0.1

Governance v1.0に付属する最小の論理設計。DBやCSVの実装仕様ではない。パイロットの列対応を確認し、変更案はYuichiと合意してから採用する。

## 4つの中心エンティティ

| エンティティ | 役割 | 最小項目案 |
| --- | --- | --- |
| Person | 人物 | person_id、name |
| Organization | 学校・チーム等の組織 | organization_id、name |
| Career | 人物の組織への所属・経歴 | career_id、person_id、organization_id、role、start、end |
| Source | 根拠資料 | source_id、title、publisher、urlまたは原資料の参照先、accessed_at |

IDは一意で安定した内部識別子とし、氏名をIDにしない。CareerはPersonとOrganizationを参照する。同名人物は氏名一致だけで統合しない。組織名の変更や同名組織も自動統合しない。

## 出典の対応

Person・Organization・Careerの各事実項目に、source_idと資料内の位置（PDFページ、表、Excelシート・行など）を対応させる。複数のSourceを利用できるようにする。項目と出典の対応表は付随記録として扱い、保存形式は取込時に決める。1件の出典が行全体の全項目を証明するとはみなさない。

Sourceのtitle等は資料で確認できる値を記録する。publisher等が不明なら不明のまま残す。accessed_atは実際に確認した日付とする。出典の実在や該当箇所を確認していない場合は候補に留める。

## 不明値・日付

不明はnull相当とし、0や推定値で埋めない。具体的な空値表現は保存形式を決める際に統一する。年月日が判明している場合のみYYYY-MM-DD、年のみ判明している場合はYYYYなど、判明した精度を保持する。年だけの情報を1月1日に変換しない。endの不明値だけで「現在も所属」と断定しない。入学年・卒業年を年齢等から計算して事実扱いしない。

## 検証と承認の付随記録

データ本体とは別に、対象IDと版、処理段階、QA結果、検証結果、不明点、出典対応、人間の承認記録を追跡する。詳細は[DATA_POLICY](DATA_POLICY.md)を参照。これらは運用記録であり、中心エンティティを追加するものではない。

## 将来の自動検証

IDの重複、参照先の存在、必要項目、出典参照、日付形式と同じ精度で比較可能な期間の前後関係を検証する。スキーマ適合は史実の正しさを保証しない。曖昧な人物同定や矛盾は人間の判断へ回す。検証プログラムは未実装。

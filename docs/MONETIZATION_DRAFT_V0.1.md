# マネタイズ方針 Draft v0.1

作成日：2026-09-20
状態：検討案。商品、価格、公開時期、スポンサー条件は未決定

## 事業コンセプト

Japan Basketball Archiveは、無料の人物名鑑だけを作るのではなく、出典付きの構造化データから検索、分析、レポート、事業者向けデータ提供へ段階的に発展させる。

```text
Free Archive
      ↓
Unique Data
      ↓
Analytics / Report
      ↓
Sponsor / B2B / API
```

最初の商用テーマ候補を **Japanese Basketball Talent Pipeline** とする。B.LEAGUE現役・経験者から大学、高校、中学への所属経路を優先して整理し、人物ページの検索価値と横断分析の価値を同じデータから高める。

## 最初に検証する価値

次の問いに、Sourceへ追跡できる構造化データから回答できる状態を目指す。

- B.LEAGUE選手を多く輩出している高校・大学はどこか
- 高校から大学への主な進学経路は何か
- 大学別、都道府県別、世代別のプロ輩出状況はどう変化しているか
- 強豪高校の卒業後キャリアはどのように分岐しているか

ランキングや人数を公開・販売する前に、対象期間、母集団、集計条件、欠損、CANDIDATEとMASTERの違いを明示する。登録されていない人物を「該当者なし」と扱わない。

## 優先するデータ収集

当面は次の順序を優先する。

```text
B.LEAGUE現役・経験者
        ↓
大学・専門学校等
        ↓
高校
        ↓
中学・育成年代
```

1人あたりの基本単位はPerson、Career、Organization、Sourceとする。高校・大学・プロの経路、各所属を裏付けるSource、資料内位置を先に整え、身長・体重等の補助属性は公式資料で確認できる場合だけ追加する。

人物数だけを増やすのではなく、次の2点を同時に測る。

- Source付きCareerの増加数
- 高校→大学→プロを連続して確認できた人物の割合

## 収益化の順序

### Phase 1：Build

- Data Factoryの小規模実証
- 100人、500人、1,000人を節目としてデータ量と品質を測定
- 無料の人物・学校ページと基本検索を改善
- Search Console / Analyticsから実際の検索需要を観察

人数は公開・販売の自動条件ではない。Source追跡率、QA差戻し率、訂正率を合わせて判断する。

### Phase 2：First Revenue

- 任意の支援導線「Support Japan Basketball Archive」の検討
- 関連商品のアフィリエイトを必要最小限で試験
- 独自データを使った小規模なデジタルレポートを試作

最初の商品候補は **Japan Basketball Talent Report**。新たな記事調査を別工程で行うのではなく、承認済みデータからPython等で表・グラフ・注記を生成する。

### Phase 3：Product

- 学校、世代、地域等のTalent Pipeline分析
- スポンサー企画を1社規模で試験
- Premium Analyticsの需要と価格を小さく検証

無料側では人物・所属・出典の閲覧を中心とし、有料候補は横断検索、比較、集計、レポートとする。

### Phase 4：Data Business

- B2Bレポート
- 条件付きCSV Export
- API
- Custom Research
- Data License

対象顧客候補はメディア、スポーツ関連企業、学校・大学、研究者、ゲーム・スポーツテック事業者等。仕様、利用条件、再配布範囲、更新頻度、訂正方法を商品化前に決める。

## 収益源の仮説

| 収益源 | 開始時期の目安 | 規模の仮説 | 相性 |
| --- | --- | --- | --- |
| Support / 寄付 | 早い | 小 | ○ |
| Affiliate / 広告 | 早い | 小〜中 | △ |
| Sponsor | 中期 | 中〜大 | ◎ |
| Premium Analytics / Report | 中期 | 大 | ◎ |
| B2B Data / API | 長期 | 大 | ◎ |

広告PVの最大化を最初の中心目標にしない。無料Archiveで検索価値を作り、独自分析、スポンサー、B2Bへつなげる。

## 編集と収益の分離

- スポンサーはデータの採否、ランキング、人物の表示順位、QA、Master承認に関与しない。
- スポンサー表示と編集コンテンツを画面上で区別する。
- 広告、アフィリエイト、提供記事はその関係を明示する。
- 分析商品は原則としてHUMAN APPROVAL済みのMASTERを集計元にする。
- CANDIDATEやVERIFIEDを試験分析に使う場合は外部販売せず、状態と限界を明示する。
- 推定値、欠損、母集団の偏りを隠さない。

## 技術・データ面の前提

```text
MASTER DATA
     ↓
再現可能な集計処理
     ↓
Tables / Charts / Notes
     ↓
Web Analytics / Report / CSV / API
```

Web、レポート、CSV、APIを別々に手入力しない。同じ版の承認済みデータと集計条件から生成し、商品やグラフから使用したデータ版とSourceへ追跡できるようにする。

将来の分析に備えて、現在から次を記録する。

- 人物・組織の安定ID
- Careerの開始・終了時点と未確認状態
- Organization種別と所在地候補
- Source ID、発行元、URL、資料内位置、確認日
- データ状態と承認記録

Competition、Game、Stats等のスキーマ拡張は、本方針だけでは承認しない。分析に必要な最小項目と既存設計への影響を確認して別途合意する。

## 検証指標

事業性とデータ品質を同時に確認する。

- 月間検索流入と選手・学校ページの閲覧数
- 検索語とサイト内検索の需要
- Source付きCareer数と連続経路の完成率
- QA差戻し率、訂正率、未解決件数
- レポートの予約・購入・アンケート反応
- 支援導線の利用率
- スポンサー候補への説明・商談反応

売上だけでなく、訂正率や出典追跡率が悪化していないことを確認する。

- Support機能の決済サービスと会計・表示方法
- スポンサー商品の範囲、価格、審査基準
- Premiumで提供する検索・分析機能
- B2Bデータの利用規約、ライセンス、個人情報・著作権の確認

## 次の判断ポイント

まずB.LEAGUE現役・経験者を起点とした100人規模の経路データを作り、次を確認する。

1. 高校→大学→プロの集計が現在の設計で再現できるか
2. 欠損とHOLDが分析結果へ与える影響を説明できるか
3. 検索需要のある学校・選手・経路が見えるか
4. 最初の無料分析サンプルを1本作れるか

この結果を確認してから、商品名、価格、販売時期を決定する。

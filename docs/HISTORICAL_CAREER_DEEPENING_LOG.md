# 過去所属チーム深掘りログ（既存選手向け）

作成日：2026-09-23

## 目的

Yuichiからの指示「深掘り（過去所属チーム）の本格展開」を受け、既にMaster/Candidateに登録済みの選手について、現所属クラブより前の過去所属チーム（高校・大学・過去のプロクラブ等）の記録が欠落していないかを体系的に確認していく取り組みのログ。辻直人（batch_007/wave_08）で行った単発のテストケースを、全登録選手を対象に本格展開したもの。

このログは、個々のWave（batch_004/wave_XX、batch_006/wave_XXなど）のREADMEに書くには細かすぎる「横断的な進捗・重複防止の記録」を1か所にまとめるためのもの。実際のCANDIDATEデータ（CSV）は、対象選手の**元の登録Batch**に新しいWaveとして追加する（cross-cuttingな専用Batchは作らない。理由は「運用ルール」参照）。

## 運用ルール（今後のWaveでも踏襲する）

1. **深掘りWaveは対象選手の元の登録Batchに追加する。** 辻直人はbatch_007由来なのでbatch_007/wave_08に追加したように、長島エマニエルはbatch_006由来なのでbatch_006/wave_03に追加した。新しいCross-cutting専用Batchを作る案（batch_008）も検討したが、以下の理由で採用しなかった。
   - サイト側の`build_site_candidate_data.py`は、CANDIDATEデータをBatch単位でまとめて処理する設計になっている（あるBatch内の複数Waveのperson/organization/career/evidence/decisionを合算してから公開データを組み立てる）。対象選手の基本Person行が「そのBatchの中に無い」と、深掘りWaveで追加したCareer/Evidenceだけを孤立して持っていても、正しく組み立てられない。
   - なお実際に検証した結果、**Master昇格済みの人物はそもそも`build_site_candidate_data.py`が意図的にスキップする**（`master_person_ids`に含まれる場合は候補データを出力しない）ため、深掘りWaveの内容はBatchの選び方に関わらずHUMAN APPROVAL・VERIFIED昇格までは公開サイトに一切表示されない。これはガバナンス上正しい挙動（未承認データを承認済みのように見せない）であり、バグではない。
2. **新しい調査を始める前に、対象選手の元Batch・元Waveに既存のissue（特にHOLD状態のもの）や、未昇格のCANDIDATE Career行が無いか必ず確認する。** 今回、河合瑠那・長岡大杜については、まさにこの確認によって「実は追加調査不要（既にbatch_004/wave_02でSUPPORTED・READY化済み、単にHuman Approval待ちなだけ）」と判明した。これを見落とすと、同じ組織参照に対して重複したCareer IDを発行してしまうガバナンス上のリスクがある。
3. 深掘りWaveの成果は、対象選手の元Batchの`README.md`に「## Wave N（深掘りWave）」として記載する。このログには、複数Batchにまたがる横断的な選定理由・判明事項だけを記録する。

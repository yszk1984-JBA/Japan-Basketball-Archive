# データ量と品質を並行して高める運用 v0.1

作成日：2026-09-19
状態：運用方針をYuichiが承認（2026-09-19）、Codex直接調査方式への変更を承認（2026-09-20）

## 目的

1人の不明点をすべて解決するまで全体を止めず、出典で確認できた項目を小さなバッチで積み上げる。未確認項目は同じ人物の確認済み項目から分離し、CANDIDATEに保留する。

この方針は調査量を増やすための運用であり、QA、HUMAN APPROVAL、Master承認を省略しない。

## バッチ単位

- 1バッチは原則10〜20人。
- 1回の調査Waveは1〜6人で調整し、標準4人から試す。詳細は[調査人数の適応運用](RESEARCH_BATCH_SIZING_V0.1.md)に従う。
- B.LEAGUE公式選手プロフィールを入口にする。
- 高校、大学、プロ所属は、各組織・大会・競技団体の公式資料を優先する。
- 難しい人物だけを別の例外キューへ分離する。
- Batch 001で測った形式を再利用し、人物ごとに独自形式を作らない。

## 1人あたりの最小確認範囲

1. Personの氏名
2. 出身高校または直前組織
3. 大学または最初のプロ所属
4. 各Careerのrole
5. 項目別のSourceと資料内位置
6. 表記揺れ、期間、人物同定等の未解決事項

生年月日、身長、体重、ポジション等は公式資料で確認できる場合だけ候補に含める。Person / Career / Organization / Sourceの中心設計を拡張せず、追加属性は項目別Evidenceとして保持する。

## 項目単位の判定

| 判定 | 扱い |
| --- | --- |
| READY_FOR_VERIFIED_REVIEW | 公式資料の該当箇所で値を直接確認でき、未解決の矛盾がない。Yuichiのレビュー対象へ送る |
| HOLD_CANDIDATE | 出典不足、矛盾、人物同定、組織不明等がある。CANDIDATEに残す |
| REJECT_CANDIDATE | 別人、誤記、無関係資料等が判明した。理由を残して採用対象から外す |

同じ人物でも、確認できた項目はREADY、期間等の未確認項目はHOLDに分けられる。人物全体を一括で確定しない。

## 高速化する部分

- B.LEAGUE、クラブ、JBA、大学連盟の公式URLをCodexが直接確認する。
- 公式プロフィールから定型項目を抽出する。
- URL、取得日、発行元、項目名を定型CSVへ記録する。
- ID重複、参照切れ、必須項目、日付順、判定値をPythonで検査する。
- 同じ公式資料を複数人で再利用する場合も、項目ごとの該当位置を残す。
- 公式資料が見つからない人物だけをFelo・Geminiの例外調査へ送る。
- Claudeは各人物の検索ではなく、10〜20人分が揃った後のバッチQAに使用する。

## 人間が確認する部分

- 同姓同名や表記違いの人物同定
- 複数資料が矛盾する場合の採否
- VERIFIED候補の差分と出典
- HUMAN APPROVALの対象版・範囲
- Masterへの反映

## 調査の停止条件

公式プロフィール、所属組織、大会・競技団体の主要資料で確認できなければ、そのバッチではHOLDとする。検索結果が増えない状態で同じ人物の調査を続けず、例外キューへ移す。

二次資料だけの値は、一次資料が見つかるまでCANDIDATEに留める。推定した入学年・卒業年、所属継続、役割の引継ぎは登録しない。

## バッチ完了条件

- 全人物の確認対象項目がEvidenceまたはIssueに結び付いている。
- Python構造検査がPASSしている。
- READY、HOLD、REJECTの件数を報告できる。
- HOLDが残っていても、理由と次の確認先が記録されていればバッチを区切れる。
- VERIFIED、HUMAN APPROVAL、MASTERを自動で更新していない。

## 次の実行単位

Batch 002は10人分のCANDIDATE、構造QA、次段階レビュー資料、例外キューを作成した。B.LEAGUE公式の福岡第一高校出身者はPilot Batch 001とBatch 002で全員を調査対象にした。

Batch 003は10人・18 CareerのVERIFIED候補作成まで完了した。Batch 004 Wave 1はFelo・Geminiを経由して2人を処理したが、Codexによる再確認との重複が大きかった。Wave 2以降はCodexが公式資料を直接確認してCANDIDATEを作成する。福岡第一高校をコアに、B.LEAGUE、B3、B.NEXT、NBA等のプロCareerを確認できる人物を優先する。調査人数は2人に固定せず、標準4人、難しい人物は1〜2人、定型処理は最大6人で調整する。通常経路で解決しない項目だけを外部AIの例外調査へ送る。契約、登録、出場、ドラフト候補は引き続き分離する。

Batch 004は10人・38 CareerのVERIFIED候補作成まで完了した。Batch 005 Wave 1は、B.LEAGUE公式戦出場を確認できる崎濱秀斗・轟琉維を新規対象とし、既存の佐藤涼成・河合瑠那のプロCareerを更新する。4人Waveで新規追加と既存品質向上を同時に測る。
